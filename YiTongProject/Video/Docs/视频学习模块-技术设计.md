## Summary

- 基于现有 `Objective-C + UIKit + AVPlayer + AFNetworking` 工程实现竖向刷视频模块，入口为底部导航中间 Tab 的「视频」；**竖滑手势、弹性/阻尼、分页吸附及 PRD 未穷尽的刷流细节**均以 **抖音（iOS）竖滑短视频 Feed 已实现效果**为体验标准（见 **§2.1**）。
- 页面结构按 PRD 固定为：`顶部分类标签栏 + 中间视频播放区 + 右侧悬浮操作区 + 左下角信息区`，其中只有视频内容上下切换，其他 UI 固定不随视频滚动。
- V1 覆盖四类能力：`推荐刷流`、`分类刷流`、`收藏列表与收藏内刷流`、`分享/文本页跳转`。
- 技术重点是：`首屏秒开`、`连续刷无感补货`、`分类切换响应快`、`播放器稳定`、`收藏与推荐复用同一套播放/数据架构`。

## 流畅度与抖音对标（滑动观看）

本质目标：**连续竖滑时尽快出画、少黑屏、少卡顿、单声道**；**手势与动效层面与抖音（iOS）竖滑短视频 Feed 已上线效果对齐**（见 **§2.1** 总原则）。工程上仍采用 **单 `AVPlayer` + Cell 挂载/解绑 + 元数据与媒体分层预取**。下列为性能与数据向约定，避免「只预取下一条、回滑顿」或「多分类实例抢带宽」等坑。

1. **双向媒体预热**：除「当前之后的 2～3 条」外，对 **紧邻上一条（若存在）** 至少做轻量 `AVURLAsset` / `AVPlayerItem` 准备或同等预热，保证 **快速往回滑** 时首帧仍可控（强弱可分级：后向优先、前向降级）。
2. **非当前分类降载**：横向切换后，**非可见分类**的 Feed 暂停媒体预热与高优先级请求，仅保留已缓存快照/内存 buffer，避免多路 `ShortVideoFeedViewController` 并行抢 `PlayerSessionManager` 与网络。
3. **首帧 KPI**：在 Wi‑Fi / 4G 常网环境下，**当前条**从成为当前页到首帧可见，与 PRD **≤1.5s** 对齐；弱网允许 **封面 + 重试**（见 `Test Plan`），不卡死主线程。
4. **400ms 指标**：**分类切换**到目标分类首条开始播放/可交互，与 PRD **≤400ms** 对齐（已有缓存路径）；**单次滑动分页结束**到当前条开始播放的体感延迟，**目标同级**（依赖预热与主线程负载，真机以 **Instruments / 录屏计时** 辅助验证）。
5. **列表末态（与抖音对齐，见「流边界」）**：已在产品确认下采用 **已加载列表内环形切换**（非「划到死墙」）；环形 **首尾相接处** 的阻尼与回弹仍须满足 **§2.1** 抖音对标走查。
6. **`UICollectionView` 性能**：整页分页 + 少量可见 cell，避免在 `scrollViewDidScroll` 做重逻辑；封面解码尺寸与 **离屏解绑** 与 §6 一致，减少内存峰值引起的掉帧。

## Key Changes

### 1. 导航与页面骨架

- 在 `UITabBarController` 中将中间“练习” Tab 替换为“视频” Tab，进入新页面 `VideoTabViewController`。
- **登录与 Tab / Deep Link（V1 暂定，已取消进房拦截）**：**不**在点击「视频」Tab 或 Deep Link 进应用时做统一「先登录再进页」拦截；未登录亦可进入 `VideoTabViewController` / 视频流（若接口对匿名仅返回空列表，以实现为准）。**收藏、分享等需账号能力**仍在用户操作时走现有 `LoginManager`（见 **§7**）。
- `VideoTabViewController` 本身不显示返回按钮、不显示导航栏标题，只保留顶部标签栏。
- 顶部标签栏固定 4 个分类，按 PRD 顺序：
  - `推荐`
  - `成语故事`
  - `神话传说`
  - `封神演义`
- `封神演义` **始终显示标签位**；后端暂无数据时该分类下为 **空态插图 + 说明文案**（产品已确认：显示 + 空态，不隐藏 tab）。
- 页面主体采用“两层滚动容器”：
  - 横向：分类容器，负责左右切分类
  - 纵向：每个分类自己的刷流容器，负责上下切视频
- 横向容器建议使用 `UIPageViewController` 或横向分页 `UICollectionView`，每个分类对应一个独立 `ShortVideoFeedViewController` 实例，彼此缓存互不污染。

### 2. 刷流容器与交互

- 每个分类内的视频流使用 `UICollectionView + 垂直整页分页` 实现，不使用 `UITableView`。
- 每屏只展示一个视频单元，视频区域固定 16:9 居中，超出部分不裁切拉伸，不足区域上下纯黑填充。
- 纵向滑动只切当前分类下的前后视频：
  - 上滑：下一条
  - 下滑：上一条
- 顶部标签、右侧按钮、左下信息区都在 feed 外层容器上，固定悬浮，不跟着 cell 复用和滚动。
- **「切换动画」指什么**：指 **同一分类内竖滑**，从当前视频**切到上一条/下一条**时的**画面过渡**（与分类横向切换无关）。**产品要求与抖音一致**：以 **`UICollectionView` 垂直整页分页** 实现 **手指跟手滚动**，松手后 **减速并吸附到相邻整屏**；视觉上为 **整屏内容沿 Y 轴连续位移**（上/下一条整页掠过），**不以全屏淡入淡出作为条与条之间的主过渡**。封面到首帧可保留 **极短局部 alpha 过渡**（避免闪黑），与抖音常见体验一致；**不做**复杂 3D 转场。
- 当前页切换判定以分页结束时机为准，不在拖动过程中频繁切换真实播放状态。

#### 2.1 抖音体验对标：弹性、阻尼与未列明细节（产品已确认）

- **总原则**：除 PRD 与本文已**逐条写明**的功能、布局、接口外，凡 **竖向刷流相关**的交互与动效细节——包括但不限于 **纵向弹性与边界回弹（rubber-banding）**、**拖动跟手与松手后的减速曲线**、**分页吸附触发距离/速度阈值**、**快速甩滑的惯性多屏衰减**、首尾（及 **环形列表** 接缝处）的 **阻尼感**、与滑动联动的 **细微停顿或回弹**——**均以抖音（iOS）当前主流版本竖滑短视频 Feed 的已实现效果为唯一体验标准**。不另行发明一套「自定义阻尼公式」作为产品依据；**验收以同机型并排录屏 + 产品走查通过为准**（竞品行为对齐，不涉及代码或素材拷贝）。
- **实现侧说明**：在 UIKit 内通过 `UIScrollView` / `UICollectionView` 的 **`bounces` / `alwaysBounceVertical`**、`decelerationRate`（`UIScrollViewDecelerationRateNormal` / `Fast`）、整页 `itemSize` 与 `scrollViewWillEndDragging` → `targetContentOffset` 等组合 **逼近抖音**；若系统默认仍与走查有差距，允许 **微调减速率、吸附逻辑、最小拖动距离** 等，直至与抖音体感一致。
- **禁止**：为图省事 **关掉纵向弹性** 或做成 **无回弹的「死区滑动」**，除非走查证明与抖音在该场景下一致。
- **与环形列表**：见 **「流边界」** 已定稿的 **已加载列表内环形竖滑**；在 **末条↔首条** 切换时，用户手指感受到的 **弹性、阻尼、是否允许轻微 overscroll 再回弹**，仍以 **抖音在可循环/长列表末端的实际手感** 为参照，由实现迭代至走查通过。

### 3. 数据域与上下文设计

- 抽象统一的 `FeedContext`：
  - `recommend`
  - `idiom`
  - `myth`
  - `fengshen`
  - `favorites(categoryScope optional)`
- 每个 `FeedContext` 持有独立的：
  - 内存 buffer
  - cursor
  - 本地快照
  - 媒体预热队列
  - 当前播放 index
- 收藏页进入刷流时仍复用同一个 `ShortVideoFeedViewController`，只是 context 变为 `favorites`，并且数据边界锁定在收藏集合内。
- 客户端统一模型 `VideoFeedItem`：
  - `videoId`
  - `title`
  - `category`
  - `summary`
  - `playURL`
  - `playURLType`
  - `coverURL`
  - `fullTextURL`
  - `isFavorite`
  - `shareURL`
  - `cacheKey`
  - `cursorToken`
  - `durationMs`
- PRD 给出的 `url` 按 `HLS 优先、MP4 兼容` 设计。
- `full_text_url` 作为“点击查看全部”的页面入口；V1 默认用 `WKWebView` 容器承接，避免同步开发一套原生文本详情页。

### 4. 接口与补货策略

- 推荐/分类流统一采用 cursor 模式，不用 page 模式：
  - `POST /video/feed/bootstrap`
  - `POST /video/feed/next`
- 请求参数至少包含：
  - `category`
  - `cursor`
  - `pageSize`
  - `lastVideoId optional`
- 返回结构至少包含：
  - `items`
  - `nextCursor`
  - `hasMore`
  - `ttlSec`
- 收藏能力接口：
  - `POST /user/videoFavorites/list`
  - `POST /user/videoFavorites/toggle`
- 单次拉取建议 8 到 12 条；客户端维持：
  - `targetBufferCount = 15`
  - `lowWaterMark = 5`
- 当当前 index 后剩余未消费条目小于等于 5 时，后台静默补货，不展示 footer，不中断滑动，不出现“加载更多”感知。
- 分类首次进入时先用该分类本地快照渲染，再异步刷新 `bootstrap`。
- 分类切换时若目标分类已有内存缓存，直接秒开，不等待网络。
- 若目标分类无缓存但有本地快照，先显示快照第 1 条，再异步拉取最新数据。
- 若完全无缓存，展示封面骨架和黑底占位，不展示全页菊花。

### 5. 首屏秒开与预加载

- 预加载拆成 3 层：
  - 元数据预取：提前拿后续 10 到 15 条 item
  - 图片预取：封面、分享缩略图走 `SDWebImagePrefetcher`
  - 媒体预热：当前条后续 2 到 3 条做 `AVAsset/AVPlayerItem` 预热
- 启动进入视频页时：
  - 先读本地 `FeedSnapshotCache`
  - 直接渲染最近成功快照
  - 优先尝试绑定上次已预热成功的视频项
  - 后台并行刷新最新 `bootstrap`
- HLS 方案：
  - 提前创建 `AVURLAsset`
  - 提前生成 `AVPlayerItem`
  - 配置 `preferredForwardBufferDuration`
  - 当前页展示时尽量直接 attach 已准备 item
- MP4 方案：
  - 先显示封面
  - 提前初始化 asset
  - 如有必要再做 Range 预取到临时目录
  - V1 不引入复杂本地代理缓存，避免实现风险过高
- 切到下一条时遵循固定顺序：
  - 新 cell 先展示封面
  - attach prepared item
  - 收到 ready/首帧信号后再隐藏封面
  - 失败时保留封面与重试态，不出现黑屏闪一下
- 本地缓存分层：
  - `FeedSnapshotCache`：保存元数据快照，建议落磁盘 JSON 或 SQLite，不继续沿用 `NSUserDefaults`
  - `MediaWarmCache`：临时媒体缓存目录，按 LRU 淘汰

#### 5.1 产品验收口径：预加载、启动首屏与「禁止全屏转圈」

以下与「**在看的时候预载下面几条**」「**启动先显示上次预加载/缓存内容**」「**不要因刚拿到新视频地址就出现整页加载转圈**」**逐条对齐**，实现须满足；与上文 §4、§5 条款一并验收。

- **观看中预载（边播边拉）**：当前条播放期间，须并行执行：**(1)** 按 §4 **`lowWaterMark` / `targetBufferCount` 静默补货元数据**（后续多条 `playURL` 提前进 buffer）；**(2)** 按本节 **媒体预热** 对 **当前索引之后的若干条**（并与 **「流畅度」** 中 **双向预热** 结合，兼顾回滑）做 `AVURLAsset` / `AVPlayerItem` 准备。目标是：用户 **上/下滑到下一屏时**，尽量 **命中已预热或至少已取 URL+封面**，避免「停在某条才开始拉下一条地址」的冷启动感。
- **启动 / 再次进入视频 Tab**：流程保持 **先读 `FeedSnapshotCache` → 用快照立刻铺 UI（封面/标题等）→ 优先 attach 上次会话已预热成功、仍在 `MediaWarmCache`/内存有效期内的项**；**后台**再请求最新 `bootstrap`。在 **新接口返回、新 `playURL` 生效前**，界面应表现为 **延续上一屏可见内容或封面静帧**，**不得**单独因「等待拉流解析」弹出 **全屏 blocking 转圈** 作为主态。
- **首次见到的新 URL（含 bootstrap 刚刷新）**：仍遵循 **封面（或骨架）占位 → 并行创建/attach item → `readyForDisplay`/首帧后再露画面**；**禁止**以 **整页菊花** 作为默认等待态；仅 **明确失败** 时允许 **内联重试/轻量提示**（与 §「流边界」错误占位一致）。

### 6. 播放器架构

- 新建 `PlayerSessionManager`，集中管理：
  - 单活跃 `AVPlayer`
  - `AVPlayerItem` 生命周期
  - KVO 和通知
  - time observer
  - 前后台切换
  - 音频焦点
- 现有 `VideoPlayerView` 保留为渲染层，但不再自己主导业务播放链路，改为受 `PlayerSessionManager` 驱动。
- 同一时刻只允许一个视频真正播放和出声。
- 每个 feed cell 不长持有独立 player，只在显示时挂接 session。
- 离屏 cell 立即解除绑定，只保留轻量状态和封面。
- 全屏逻辑：
  - 继续使用现有全屏播放器页思路
  - 共享当前 `AVPlayer`
  - 进入/退出全屏不重建播放资源
  - 全屏仍保持 16:9，黑边允许存在
- 和现有故事音频共存时，短视频播放优先级更高，进入播放后主动抢占音频焦点。

### 7. 固定悬浮 UI

- 右侧固定操作区：
  - 收藏
  - 分享
- 收藏逻辑：
  - 登录态下本地先更新按钮态，再发服务端同步
  - 失败回滚并提示
  - 非登录态点击收藏走现有登录链路
- 分享逻辑：
  - 生成分享链接：`https://shiyi.yitong.com/app/video?id={video_id}&from=share`
  - 实际链接由后端补防爬参数，客户端只消费最终分享 URL
  - 第一版分享面板采用自定义 action sheet，不直接依赖系统 share sheet 顺序
  - 国内版顺序：
    - 微信好友
    - 朋友圈
    - 复制链接
  - 国际版顺序：
    - WhatsApp
    - Instagram
    - 复制链接
- 分享落地策略：
  - 若目标 App 已安装则优先唤起
  - 若未安装则复制链接或跳系统打开分享链接
  - Deep Link/H5 落地页和商店跳转由后端落地链路承接，客户端不在 V1 自己拼复杂跳转分支
- 左下信息区固定展示：
  - 标题
  - summary
  - “点击查看全部”
- “点击查看全部” 跳转 `VideoTextWebViewController`，用 `full_text_url` 打开，不覆盖当前视频页状态；用户返回后应恢复到原视频和位置。

### 8. 收藏页与收藏内刷流

## Deep Link / Universal Link（已安装 App）

### 客户端不可省略的责任

后端落地页可处理「未安装跳转商店」等场景；**App 已安装时**，必须通过 **Universal Link / URL Scheme** 进入应用并**打开指定视频**，且在 Tab 与 Feed 栈上行为可预期。

### 建议组件

- 集中解析：`VideoDeepLinkRouter`（或由现有路由总线扩展），在 `AppDelegate` / `SceneDelegate` 的 `continueUserActivity` / `openURL` 等入口调用。
- **输入**：URL 中 **`video_id`（必填）**、可选 **`from`**（如 `share`）、可选 **`category`**（若后端约定）。
- **输出动作**：
  1. 切换根 Tab 至 **「视频」Tab**（与 **中间 Tab「视频」**、`VideoTabViewController` 一致）。
  2. 构造 **`FeedContext`**：分类优先顺序建议为 — URL 指定分类 > 服务端随单条元数据返回的推荐分类 > **当前 Tab 默认分类**。
  3. 打开 **`ShortVideoFeedViewController`**（或容器内子页），携带 **`entryVideoId`**；若列表中暂无该条，先走 **单条元数据/插桩拉取** 再插入当前 cursor 流（实现细节与接口以联调为准，但路由目标必须写死为「进视频 Tab + 目标 id」）。

### 登录态

**与 Tab 一致**：Deep Link **不强制**先弹登录；若后续产品恢复「进房前登录」，在 **Assumptions** 单独立项并改路由。

### 与现有 Tab 栈关系

- Deep Link **不**新建独立 window 根；在现有 `UITabBarController` 上 **select 视频 Tab**，必要时 **pop 至该 Tab 根导航栈** 再 push/present Feed，避免多层残留导致「返回」行为混乱。

## 流边界、异常态与去重（与 UI 占位一致）

### `hasMore == false` 与「类抖音」末态（产品已确认）

- **目标体验**：与 **抖音** 类似——在**当前已加载列表**内可 **无限循环竖滑**：滑到 **最后一条**再继续 **上滑**回到 **第一条**；在 **第一条**再继续 **下滑**回到 **最后一条**（环形索引，无「划到头死墙」+ 仅提示文案的停顿感）。
- **`hasMore == true`**：向后仍可按 cursor **静默补货**，补货逻辑与 §4 一致；环形指**当前内存列表**的有效范围。
- **`hasMore == false` 且列表多条**：仍按上款在**已加载集合**内环形切换，**不**再依赖服务端 next。
- **`hasMore == false` 且仅 0 条**：内容区空态（见下节）；**仅 1 条**：上下滑可为 **同一条重播**或轻微阻尼（实现取更顺滑的一种，避免黑屏）。

### 零条 / 单条

- **某分类列表长度为 0**：展示 **空态插图 + 说明文案**（与「不用整页菊花」策略一致：分类栏可立即显示，内容区为空态）。
- **仅 1 条**：仍支持纵向分页 UI；边界行为见上节（单条环形/阻尼）。

### 网络失败与重试

- **首屏 bootstrap 失败**：内容区 **错误占位 +「重试」按钮**（可选下拉刷新与按钮二选一，V1 至少一种）；**避免**全屏阻塞菊花。
- **加载更多（next）失败**：底部或当前 cell **toast / 内联错误条 + 重试**，不丢弃已成功页；**cursor 不前进**直至成功或用户离开。
- **HTTP 4xx/5xx**：区分 **可重试（5xx/超时）** 与 **不可重试（4xx）**；4xx 可展示明确文案（如内容不存在）并支持回退到 Tab 默认态。

### 去重策略

- **客户端**：维护已展示 **`videoId` 集合（或有序去重）**，追加 `next` 响应时过滤重复项；若本页全被过滤则**自动再请求下一页**（设最大次数防止死循环）。
- **服务端**：联调约定 **cursor 单调不回退**；若仍出现重复，以客户端过滤为兜底，保证 **滑动体验无连续重复**（与测试计划一致）。

## 收藏列表入口与导航（相对「视频页无返回」）

### 入口（定稿）

- **主入口**：底栏 **「个人中心」** Tab → `ProfileViewController` 底部功能区 **「收藏」** 行 → 进入收藏列表（当前工程为 `FavoitesViewController`，视频模块落地时可 **替换为或内聚到** `FavoritesListViewController`，保持同一入口与 `hidesBottomBarWhenPushed = YES` 行为）。
- **与 PRD 关系**：PRD 所述「视频页无返回、仅靠底栏」指 **视频 Tab 根页** 不设系统返回；**收藏列表从个人中心进入，使用导航栈 `push`，具备返回按钮**，二者**不矛盾**。

### 与视频 Tab 的并行关系

- **视频 Tab**：类 **抖音** 竖滑 Feed（交互细节见 **§2.1**），**无「返回上一页」**（仅 Tab 切换离开）。
- **收藏列表**：独立列表页，**返回**回到 `ProfileViewController`；若收藏内支持「点进竖滑子流」，子流返回应 **pop 回列表**，**不**销毁视频 Tab 根播放器会话（若与视频 Tab 共享 `PlayerSessionManager`，需约定生命周期归属）。

### `FavoritesListViewController` 与 `FavoitesViewController`

**演进替换为主路径**：以 **个人中心 → 收藏行** 为唯一主入口；新能力集中在 `FavoritesListViewController`（或等价命名），逐步替代仅空态的 `FavoitesViewController`，避免重复入口。若短期需并存（例如分内容类型），须在迭代说明中写清路由表。

## Test Plan

- **PRD 非功能 KPI（需在真机、常网基线下验收）**：当前条从「成为当前页」到 **首帧可见 ≤1.5s**；**分类切换**至目标分类首条 **可播放/可交互 ≤400ms**（有缓存路径）；**单次上/下滑分页结束**后当前条起播体感延迟 **目标与 400ms 同级**（依赖预热与主线程，以 **Instruments / 录屏+计时** 等辅助验收；V1 无客户端埋点）。
- 冷启动且本地有推荐快照时，进入视频页应先直接看到首条视频内容，再静默刷新。
- 分类首次切换到已缓存分类时，应在 400ms 内完成内容切换并开始播放。
- 连续上滑 50 到 100 条，不出现 footer、无重复视频、无黑屏闪烁。
- **抖音对标走查（必过）**：**纵向弹性/边界回弹、拖动跟手、松手减速与整页吸附、快速甩滑惯性、环形列表首尾接缝处手感**等，与 **抖音 iOS 竖滑 Feed** 在 **同机型并排**对比，**产品走查签字**；与 **§2.1** 总原则一致。
- **列表末态（类抖音）**：已加载多条时 **末尾上滑回到首条、首条下滑回到末条**（环形）；无「死墙」仅文案；`hasMore` 仍为 true 时补货行为不变。
- **去重**：同一流内滑动无**连续重复** `video_id`；必要时自动多请求下一页在合理次数内终止。
- **异常态**：首屏 bootstrap 失败有占位与重试；next 失败 cursor 不前进且可重试；4xx 有明确文案或可回退。
- **Deep Link**：已安装 App 时，从分享/外链进入能 **直接**切到视频 Tab 并定位 `entryVideoId`（**不要求**先登录；含列表暂无该条时的补拉/插入策略联调通过）。
- 快速上下滑动时，始终只有当前页有声音，离屏页不继续播。
- 视频 16:9 在不同机型上都保持比例不变，上下黑边为纯黑。
- 进入全屏与退出全屏时，不应重新请求视频或重置播放进度。
- 收藏按钮在登录态下本地状态与服务端状态最终一致；失败能回滚。
- 收藏页点击进入后，应从所点视频开始刷，且范围仅限收藏集合。
- 在收藏内刷流取消收藏后，索引和列表更新正确，空列表能正确退出。
- 点击“查看全部”进入文本页后，返回时视频页状态仍在原位置。
- 分享面板国内版和国际版渠道顺序正确；复制链接内容正确包含 `video_id` 与 `from=share`。
- 弱网场景下首帧超时允许降级显示封面，但不能整页白屏或卡死。

## Assumptions

- 这版以当前仓库为落地基线，不新开纯 Swift 架构。
- 视频协议按 `HLS 最优、MP4 兼容` 设计；若后端最终只给 MP4，V1 只能做到“尽量减少转圈”，不能承诺所有弱网场景绝对无卡顿。
- `full_text_url` 在 V1 由 `WKWebView` 承接，而不是同时开发一套原生文本详情页。
- `封神演义` 标签**始终展示**；后端暂时无数据时该分类为 **空态**（产品已确认）。
- 分享的 Deep Link、防爬参数、未安装跳商店等复杂落地链路由后端统一生成最终分享链接，客户端只做渠道分发和打开。
- **PRD 分享矛盾（终稿）**：凡与 **「分享（第一版）」** 冲突的 PRD 前文描述（含另一套链接形态或旧版「仅系统三项」等）**一律不执行**；实现与验收以 **`/app/video` + `id` + `from=share` + 自定义 `VideoShareSheet`** 为准，与 **Key Changes §7** 一致（**产品已确认**保留自定义 Sheet）。
- **登录策略（V1 暂定）**：**不**对「视频 Tab 点击」与 **Deep Link 进视频**做统一登录拦截；未登录可进 Feed（接口若限匿名则展示空态或错误占位）。**收藏、分享等**在用户触发时按 **§7** 走 `LoginManager`；若登录态中途失效，仍可按 §7「非登录态点击收藏走登录」兜底。
- **列表末态（终稿，产品已确认）**：与 **抖音** 对齐，在 **当前已加载列表** 内 **环形竖滑**（末条上滑回第一条、首条下滑回末条）；见 **「流边界、异常态与去重」**。
- **竖滑交互与动效（兜底条款）**：凡 **PRD 与本文未逐条列举**的刷流侧交互或动效（含弹性、阻尼、吸附阈值、惯性等），**默认以抖音（iOS）已实现效果为准**；若与 PRD **明文**冲突，以 PRD 为准并需产品书面裁断。
- **V1 明确不做 / 不承诺（非目标）**：
  - **客户端数据埋点**：V1 **不做**「最小埋点清单」中的事件上报（见 **MVVM-C** 小节）；后续迭代再接入。
  - **不**做复杂本地 HTTP 代理缓存、**不**在 V1 同步做一套原生全文详情页（见上）。
  - **不**将 PiP、完整无障碍（VoiceOver/Dynamic Type 全量）列为 V1 交付硬指标（可按迭代补）。
  - 客户端 **不**自建「未安装跳商店」完整分支逻辑，由后端 H5/落地页承接；App 内仅负责已安装场景路由与播放。

| **分享 `share_url`** | 客户端优先用服务端返回的 **最终 URL**（含防爬、`from=share`）；若首版仅拼模板，需后端确认是否接受。 |
| **国内/国际渠道切换** | `VideoShareSheet` 顺序依赖的 **地区/语言判断** 与现有工程（如 `LanguageHelper`）对齐方式，实现前确认一处即可。 |
| **HLS 签名过期** | 若 `url` 为短效签名，**续期或换 URL** 策略（文档未写死，联调时易踩坑，建议尽早问后端）。 |
| **工程落盘** | §9 类清单 → 具体 **子目录**、是否新建 Target、Pod 依赖（已有 `SDWebImage` 等）在拆任务时写到任务单即可。 |

**文档说明：** §7「非登录态点击收藏走登录」与 **Assumptions** 中「Tab/Deep Link 不拦截登录」并存：未登录可进 Feed，点收藏再拉登录。

## 分阶段开发步骤（推荐顺序）

**文档会不会乱？** 不大会：主干看 **`Key Changes` §1～§9**；补充规则看 **Deep Link / 流边界 / 收藏 / MVVM-C / §5.1 / §2.1**；验收看 **`Test Plan`**。开发时 **按下列阶段顺序做**，每阶段结束有可演示增量，避免一次性摊大饼。

| 阶段 | 目标（做完应具备） | 主要类/工作 |
|------|-------------------|-------------|
| **0** | 工程能编译、Tab 占位 | 定目录；中间 Tab 换「视频」；进入 `VideoTabViewController` 空壳（**不**做 Tab 登录拦截）；与 **开发就绪度** 表并行拉 API 契约 |
| **1** | 数据层可测 | `VideoFeedItem`、`FeedContext`、`FeedPageResult`；`FeedRepositoryProtocol` + `FeedRepository`（可先 **Mock** 再换真接口）；`POST bootstrap/next` 解析与错误分支 |
| **2** | 能播一条 | `PlayerSessionManager` + 现有 `VideoPlayerView` 挂载；**单页**或单 cell 内 HLS/MP4 通一路；前后台与音频焦点 |
| **3** | 竖滑换条 | `ShortVideoFeedViewController` + `ShortVideoCell` + `UICollectionView` **整页分页**；`ShortVideoFeedViewModel` 状态机（loading/empty/error）；**分页结束再换播放绑定**（§2） |
| **4** | 四类 Tab | `VideoTabViewController` + `VideoCategoryTabsView` + 横向容器；**每分类一个** `ShortVideoFeedViewController` 实例；**非当前分类降载**（流畅度 §） |
| **5** | 秒开与预载 | `FeedSnapshotCache`（磁盘快照）；`VideoPreloadManager` + 元数据/封面/媒体预热；§4 **lowWaterMark** 补货；对齐 **§5.1** |
| **6** | 浮层与互动 | 右侧收藏/分享、左下信息与「查看全部」；收藏 **乐观更新 + 回滚**；`POST videoFavorites/*` |
| **7** | 全文 | `VideoTextWebViewController`（`WKWebView`）；**push**、`hidesBottomBarWhenPushed`、**pop** 回 Feed |
| **8** | 分享 | `VideoShareSheet`（国内/国际顺序）；渠道跳转与复制链接；消费服务端 `share_url` |
| **9** | 收藏列表 | `FavoritesListViewController` 演进；点进 `ShortVideoFeedViewController(context:favorites, entryVideoId:)`；个人中心入口改路由 |
| **10** | 协调与深链 | `FeedCoordinator` 串起全文/登录/外链；`VideoDeepLinkRouter` + `AppDelegate`/`SceneDelegate`；单条缺 id 补拉（接口齐后） |
| **11** | 流边界 | **环形索引**（§流边界）；客户端 **videoId 去重**；bootstrap/next **失败与 4xx** 占位 |
| **12** | 体验收口 | **§2.1 抖音对标**走查（弹性、吸附、甩滑、环形接缝）；全屏播放共用 session；与故事音频抢占 |
| **13** | 联调与测试 | 按 **`Test Plan`** 勾选；性能 KPI（1.5s / 400ms）真机记录 |

**说明：** 若人力并行，**1 与 2**、**6 与 7** 可在依赖满足时部分重叠；**10** 依赖 Universal Link 配置与单条接口。**必须串行**的是：**2 → 3**（先能播再滑）、**3 → 4**（先单流再多分类）、**5 在 3 有基础后**加（否则预载无附着点）。
