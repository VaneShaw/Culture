# Talk 学习流 - 提交答案流程说明

## 一、当前实现（写死数据）

### 1. 整体流程

```
用户点击「提交」 → handlePrimaryActionWithCompletion → 本地判断对错 → 返回 YTUnitSubmitResult → 容器展示反馈弹窗
```

### 2. 数据来源

- **Mock 数据**：`YTMockUnitFactory.buildMockAPIResponseForSceneId:levelId:` 返回写死的 JSON
- **映射**：`buildUnitsFromAPIResponse:sceneId:levelId:` 将 `evaluation.rule.correctOptionId` 解析到 `YTUnit.correctOptionId`

### 3. 各题型判断逻辑

| 题型 | 用户答案形式 | 判断依据 | 代码位置 |
|------|-------------|----------|----------|
| 听词选图 | `selectedOptionId`（选项 id） | `selectedOptionId == correctOptionId` | YTChoiceExerciseUnitView |
| 看图选词 | `selectedOptionId` | 同上 | YTChoiceExerciseUnitView |
| 选词填空 | `selectedOptionId` | 同上 | YTFillBlankUnitView |
| 听音回应 | `selectedOptionId` | 同上 | YTListenResponseUnitView |
| 完成对话 | `selectedOptionId` | 同上 | YTCompleteDialogueUnitView |
| 句子组装 | 词块顺序拼接的字符串 | `[answer isEqualToString:correctOptionId]`（correctOptionId 复用为正确句子） | YTBuildSentenceUnitView |

### 4. 关键代码路径

- **容器层**：`TalkLearningFlowViewController.onPrimaryButton` → 调用 `unitView.handlePrimaryActionWithCompletion`
- **题型层**：各 UnitView 的 `handlePrimaryActionWithCompletion` 内直接比较并 `completion(r, nil)`
- **结果结构**：`YTUnitSubmitResult`（`isCorrect`、`correctAnswerText`）

## 二、对接接口时的改造方案

### 1. 架构思路

将「本地判断」替换为「调用提交答案接口 → 根据接口返回构造 YTUnitSubmitResult」。

```
用户点击「提交」 → 收集用户答案 → 调用提交答案 API → 解析接口返回 → 构造 YTUnitSubmitResult → completion 回调 → 容器展示反馈
```

### 2. 需要新增的组件

#### （1）提交答案服务协议

```objc
// YTAnswerSubmitService.h
@protocol YTAnswerSubmitService <NSObject>
- (void)submitAnswerForUnit:(YTUnit *)unit
                userAnswer:(id)userAnswer  // 选择题为 optionId，句子组装为拼接字符串
                completion:(void (^)(BOOL isCorrect, NSString * _Nullable correctAnswerText, NSError * _Nullable error))completion;
@end
```

#### （2）Mock 实现（模拟接口请求）

- 用 `dispatch_after` 模拟 0.5~1s 网络延迟
- 内部仍用本地 `correctOptionId` 判断对错（与当前逻辑一致）
- 便于在接口未就绪时联调 UI

#### （3）真实接口实现

- 调用后端 `POST /api/talk/submit-answer` 等
- 请求体：`unitId`、`sceneId`、`levelId`、`userAnswer`（题型不同格式不同）
- 响应体：`{ "isCorrect": true/false, "correctAnswerText": "..." }`

### 3. 改造点清单

| 位置 | 改造内容 |
|------|----------|
| `YTUnitViewProtocol` | 协议不变，仍通过 completion 回调 |
| 各 UnitView 的 `handlePrimaryActionWithCompletion` | 先收集 `userAnswer`，调用 `YTAnswerSubmitService`，在 completion 中构造 `YTUnitSubmitResult` 并回调 |
| `TalkLearningFlowViewController` | 注入 `id<YTAnswerSubmitService>`，传给 UnitView 或通过 configure 传入 |
| 新增 `YTAnswerSubmitService` | 协议 + Mock 实现 + 真实实现 |

### 4. 用户答案格式（供接口对接参考）

| 题型 | userAnswer 格式 | 示例 |
|------|-----------------|------|
| 选择题类 | `optionId` (NSString) | `@"b"` |
| 句子组装 | 拼接字符串 (NSString) | `@"现在开门了吗？"` |

## 三、模拟接口请求的实现（已接入）

### 1. 已实现组件

- **YTAnswerSubmitService**：协议定义
- **YTAnswerSubmitServiceMock**：Mock 实现，`dispatch_after` 模拟 0.6s 延迟，内部用 `correctOptionId` 判断
- **注入方式**：`TalkLearningFlowViewController` 在 `configureWithUnit` 时传入 `[YTAnswerSubmitServiceMock shared]`

### 2. 切换方式

- **使用 Mock（模拟接口）**：`submitService:[YTAnswerSubmitServiceMock shared]`（当前默认）
- **使用本地判断（无延迟）**：`submitService:nil`
- **对接真实接口**：实现 `YTAnswerSubmitService` 协议，在 `configureWithUnit` 时传入真实实现
