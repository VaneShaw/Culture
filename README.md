# Culture iOS

易通 iOS 客户端：**Objective-C + UIKit**，依赖 **CocoaPods**（AFNetworking、Masonry、SDWebImage 等）。维护期模块可沿用 MVC；新功能推荐 **MVVM-C**（ViewModel + Coordinator + 薄 ViewController）。

---

## AI 辅助研发：能力边界与在本仓库中的用法（技术向）

本仓库两条功能线（Talk 学习流、短视频）在迭代中主要在 **Cursor**（IDE + Agent）内完成 **大模型辅助编程**：利用其对代码库的全文索引、多文件编辑与终端集成，把需求拆到具体文件与符号上；重点不在「一键生成整模块」，而在提升 **规格对齐、重构安全与边界覆盖** 的效率。

| 环节 | AI 侧能力 | 工程侧落点 |
|------|-----------|------------|
| 需求 / 接口 | 从 PRD、接口文档或 JSON 样本中抽取字段语义、嵌套结构、有序列表约束 | `scene_tab_list`、有序 JSON、`talk unit` 等与 UI 状态的映射与校验 |
| 架构与重构 | 在多文件间追踪调用链，建议抽层与命名；识别重复 `switch` / 题型分支 | 题型判断收拢至 `YTUnit` 等统一入口，降低枚举变更漏改风险 |
| UIKit / 约束 | 在 Masonry 下推导多语言、长文案下的按钮与标题 **自适应布局** | 学习流主按钮、自定义弹窗左右内边距；TabBar / 收藏列表深色主题 |
| 国际化 | 从中文文案批量产出 `NSLocalizedString` key 方案与词条表 | Talk 场景弹窗、错误提示等多处文案 i18n |
| 媒体与状态 | 枚举播放器生命周期边界（前后台、全屏 dismiss、分页恢复） | 全屏视频关闭后 **host VC 查找** 与媒体分页恢复；Story 时间码 **毫秒级 seek** 与安卓对齐 |
| 视频链路 | 辅助梳理 **预热池 / 环形下标 / standby** 等等价状态，补全日志与竞态假设 | 短视频 Feed 首帧、邻条落盘、无更多数据时的环形补页与分类切换裁剪池 |

**结论**：在 Cursor 中以 AI 作为「结对工程师」加速 **接口—模型—界面—边界用例** 的闭环；生成与改写均经人工审阅，最终合入仍以 Code Review 与真机验证为准。

## `feature/20260316-fwx` — Talk 情景学习流（技术要点）

- **数据与协议**：情景对话首页对接场景接口；适配 `scene_tab_list`、有序 JSON；学习流串联 `talk unit` 与场景首页接口。
- **题型与状态**：话题页 `is_medal`、句子组装答案回填；选词填空 **反选 / 联动 / 续学可编辑**；带音频题型 **自动播放** 策略；过场页按列表索引区分中间态与收尾态。
- **视图栈与媒体**：全屏视频关闭后恢复 **媒体分页** 与 **宿主 VC** 解析；Story 音频时间码解析与 seek 精度。
- **i18n / 资源**：弹窗与错误提示国际化；难度页顶部徽章图随 **界面语言** 切换；移除「60% 进度解锁下一等级」类打断型弹窗。

**技术关键词**：学习流状态机、多题型复用、UIKit 栈恢复、`NSLocalizedString`、弱引用与异步回调中的内存边界。

## `feature/20260401-video-fwx` — 短视频与内联全屏（技术要点）

- **模块**：视频子系统搭建、Tab 接入；视频 Tab **深色底**、切图与标题栏样式（含白底黑字标题）。
- **Feed 与缓存**：短视频首页 UI 与互动布局；**首条首播**、首帧、**预热池**（邻条提前落盘、池大小与磁盘策略）；**环形 Feed**（头尾 wrap、末条冷启动、无更多数据时的补页与日志）；分类切换时 **保留当前播放** 并 **裁剪预热池**。
- **播放状态机**：竖滑切换时的状态机与绑定复位，避免错绑与残留播放。
- **内联全屏**：横屏视频内联全屏交互；进度条区域 **当前 / 总时长（分:秒）** 叠加展示。
- **收藏**：收藏列表深色主题与 `UITableView` 卡片布局。

**技术关键词**：预加载与 LRU/池化策略、环形缓冲区式下标、播放器单例与 VC 生命周期、横竖屏与内联 `UIViewController` 嵌入。

## 环境要求

- **Xcode**：以当前团队使用的版本为准；工程曾跟进较新 Xcode 与 AFNetworking 适配（见 `podfile` / `Podfile.lock`）。
- **CocoaPods**：安装依赖后使用 **Workspace** 打开工程，勿直接打开 `.xcodeproj`（除非明确不用 Pods）。

## 构建

```bash
pod install
open YiTongProject.xcworkspace
```
